A new shared reference, `skills/continuous-refactoring/references/forge-facing-writing.md`, tells every lifecycle skill how to write text that lands on the target repo's own forge (issue comments, closing notes, `out-of-scope/` entries, merge request descriptions): the reader has never seen this suite's own repo, so don't cite this suite's own file paths or use its controlled-vocabulary labels (candidate, finding, tooling-tree node, flagged candidate, and the like) as justification — state the rule or finding itself in plain words instead. `refactor-learn`'s two rejection-writing spots, `refactor-design`'s flagged-candidate issue comment, merge-request descriptions, and the branch-abandonment closing note all now point to this shared rule.
