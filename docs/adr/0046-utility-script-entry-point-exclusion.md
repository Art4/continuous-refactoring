# A non-empty `unwired_entry_points` result is an agentic judgement call, not a parser guess

## Context

Caught live on `Art4/legacy-todo`: once the `coverage-floor` node (ADR-0044) landed there, its own
generated CI-helper script — `scripts/check-coverage-floor.php`, a generic Clover-XML reader with no
dependency on the target's own classes — got misdetected as a `psr-4` **Entry point** (ADR-0042).
Nothing requires it, so `_entry_point_candidates` correctly found it unrequired; it isn't on the fixed
`_TOOLING_CONFIG_PHP_FILENAMES` list (`rector.php`, `.php-cs-fixer.php`) since its name is generated by
whichever node's own MR scope writes it, never knowable in advance. Result: `psr-4`'s autoloader-wired
criterion flipped to unfulfilled — not because the app's real request-time class loading broke
(`Bootstrap.php` was untouched), but because the detector now had one more "entry point" that
plausibly needed its own `vendor/autoload.php` wiring and didn't have it.

A first version of this fix added a second, narrower filesystem-text heuristic to the detector itself
— excluding a candidate under a conventional tooling directory (`scripts/`, `bin/`, `tools/`) whose
text never mentioned the target's own namespace. Reconsidered before landing: this is a second
special-cased exclusion rule (after `_TOOLING_CONFIG_PHP_FILENAMES`) that doesn't generalize — every
future shape of "a script that structurally can't need the autoloader" would need its own new rule,
and the judgement it's trying to encode (is this really part of the application?) is exactly the kind
of contextual call an agent is well-suited for and a fixed heuristic keeps chasing.

## Decision

The deterministic parser stays simple and honest instead: `_autoloader_wired` now returns
`(wired: bool, unwired: list[str])` — every candidate that still needs its own `vendor/autoload.php`
require, named plainly, with **no attempt to guess which of them are real application entry points and
which aren't**. `psr-4`'s own `set_node(...)` call exposes this as `details.unwired_entry_points`.

The actual judgement — is a given unwired candidate genuine unaddressed work, or a script that
structurally never needed the autoloader in the first place — moves to `php-tooling-tree/psr-4.md`'s
own Fulfilment check, read by whichever agent-driven skill is consuming this result
(`refactor-scan` proposing work, `refactor-learn` writing `Fulfilled nodes`): look at each named file;
one that never references the target's own PSR-4 root namespace and is self-evidently dev/CI/build
tooling is exempt, everything else is real. A headless, non-agent consumer of `tooling_tree.py`'s raw
JSON output (CI, this suite's own fixture harness) applies no such exemption — the raw list stands
as-is until an actual agent session reviews it.

## Considered Options

- **Directory + namespace-content heuristic baked into the parser itself** (the first version of this
  fix). Rejected — doesn't generalize past the one shape it was written for; a fixed rule chasing an
  open-ended set of future "this script doesn't really count" cases is the wrong tool for a judgement
  call, when an agent already reads this result downstream in every normal (non-headless) use of this
  suite.
- **Add the specific new filename to `_TOOLING_CONFIG_PHP_FILENAMES`.** Rejected for the same reason
  as ADR-0042's own original design already rejected it implicitly: that list is for *known, fixed-name*
  tool configs (Rector, php-cs-fixer), not for agent/tool-generated helper scripts whose names aren't
  fixed at all.
- **Silently exempt anything under `scripts/`/`bin`/`tools` with no content check at all.** Rejected —
  `bin/` in particular is also a real convention for genuine CLI *application* entry points (e.g. a
  console command needing the full DI graph); a blanket directory exemption would silently reopen the
  #194 defect class for that shape of entry point instead of closing it.
- **Keep the boolean-only `autoloader_wired` and have the agent re-run its own file-system walk from
  scratch when it wants to sanity-check a `false`.** Rejected — the parser already computed exactly
  the list an agent needs; discarding it and asking the agent to re-derive it is wasted work for no
  benefit.

## Consequences

`tooling_tree.py`: `_autoloader_wired`'s return type changes from `bool` to `tuple[bool, list[str]]`;
its one caller (`psr-4`'s own `set_node(...)` block) threads the new `unwired_entry_points` list into
`details`. No new module-level constants, no new function parameters threaded through
`_entry_point_candidates`/`_detect_entry_points` — both stay exactly as ADR-0042 originally shaped
them. `psr-4.md` gains a new "Reading a non-empty `unwired_entry_points` result" section. Three tests
in `Psr4AutoloaderWiringTests` cover the new field: an unwired ordinary entry point names itself, a
wired one reports an empty list, and — the real caught case — a generated CI-helper script under
`scripts/` is still reported (not silently exempted) by the deterministic layer, confirming the
judgement genuinely moved to the doc layer rather than just being deleted. No fixture changes needed —
none of this suite's own 8 PHP fixtures place a `.php` file under `scripts/`/`bin`/`tools`.
